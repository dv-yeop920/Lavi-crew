# 004. 이메일 인증과 연락처 프로필 분리

- 상태: 승인
- 결정일: 2026-07-15

## 배경

Supabase Auth의 이메일·비밀번호 가입과 이메일 확인 흐름을 사용하면서, 휴대폰 번호도 회원가입 시 받아야 한다. 로그인 식별자와 업무 연락처의 책임을 분리하지 않으면 인증 스키마와 공개 프로필 데이터의 경계가 불명확해진다.

## 결정

- 로그인 식별자는 `auth.users.email`이며 이메일·비밀번호로 가입하고 로그인한다.
- 운영 환경에서는 이메일 확인을 활성화하고, 확인 전에는 업무 화면 세션을 허용하지 않는다.
- 휴대폰 번호는 `public.profiles.phone`에 저장하며 로그인 식별자로 사용하지 않는다.
- `public.profiles.id`는 `auth.users.id`를 PK/FK로 참조한다.
- 가입 요청은 서버에서 초대 코드를 검증한 뒤 Supabase Auth 가입을 요청한다. 프로필 생성과 초대 코드 사용 횟수 반영은 실패 시 불완전 계정이 남지 않도록 원자성과 복구 절차를 함께 설계한다.
- 역할은 공개 가입 입력으로 받지 않고 신규 가입자는 `worker`로 생성한다. 단일 `admin`은 별도 초기화 절차로만 부여한다.
- 클라이언트 데모 세션은 제거하고 Supabase Auth의 실제 이메일 확인·쿠키 세션만 사용한다.

## 근거

Supabase Auth의 Auth 스키마는 자동 생성 API에 직접 노출되지 않는다. Supabase 공식 지침에 따라 앱에서 조회할 사용자 정보는 RLS가 적용된 `public` 테이블로 분리하고 `auth.users`의 기본 키를 참조한다.

## 결과

- 이메일 변경과 휴대폰 번호 변경은 서로 다른 유스케이스로 처리한다.
- 이메일 확인, 재전송, 비밀번호 재설정 화면과 Redirect URL 설정이 서버 구현 범위에 추가된다.
- 휴대폰 번호는 프로필 RLS와 관리자 권한 아래에서만 조회·수정하며 목록 화면에서는 마스킹한다.
