# 003. 개인 운영 데이터는 명시적으로 캐시한다

## 상태

확정 (2026-07-15)

## 배경

스케줄 변경과 출석 확정은 즉시 확인되어야 하고 급여는 확정 출석을 기준으로 계산된다. Supabase SDK 조회는 Next.js `fetch` 캐시 정책이 자동으로 적용되는 대상이 아니다.

## 결정

- 개인 스케줄, 신청 상태, 출석, 급여는 기본적으로 캐시하지 않는다.
- 공지, 포지션 목록처럼 여러 사용자가 공유하고 변경 빈도가 낮은 데이터만 서버 구현 시 명시적 캐시 후보로 검토한다.
- 캐시를 도입할 때 데이터 종류별 tag를 사용하고 관련 Server Action 성공 후 해당 tag를 갱신한다.
- `cacheComponents`와 `use cache`는 실제 조회 경계와 무효화 흐름을 구현하는 변경에서 함께 활성화한다.
- TTL과 stale 시간은 운영 요구가 확정되기 전 임의로 정하지 않는다.

## 결과

현재 Next.js 설정에는 `cacheComponents`를 켜지 않는다. 클라이언트 정적 fixture는 서버 데이터 캐시 정책으로 간주하지 않는다.
